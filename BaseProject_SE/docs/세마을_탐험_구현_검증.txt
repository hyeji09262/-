세 마을 탐험 확장

구성
- 기존 튜토리얼의 해안 지형/렌더러를 재사용한 60 x 192 타일 월드입니다.
- 별빛 마을, 해솔 항구 마을, 달빛 숲 마을: 각 주민 10명, 총 30명.
- 마을마다 주택 3채, 학교/분교, 편의점, 학원, 보건소: 총 21개 건물.
- 9종의 색/외형을 가진 건물 모델은 primitive_models_v8.bin에 캐싱합니다.
- 주민은 기존 5종의 서로 다른 실루엣에 체격/방향을 조합합니다. 이름과 대사는 30명 각각 다릅니다.
- 학교 로비에서 도서관, 체육관, 방송실을 각각 방문할 수 있습니다.
- 편의점은 물약을 종류별 최소 3개까지 보급, 보건소는 체력/마나를 회복합니다.

스토리 연결 / 조작
- F1 기존 튜토리얼, F2 독립 사냥 연습, F3 프롤로그/메인퀘스트1, F4 메인퀘스트2 유지.
- F6: 확장된 마을 탐험. 현재 이야기/전투는 정지되며 진행 단계를 초기화하지 않습니다.
- 프롤로그에서 뉴스를 확인하고 집을 나가면 우리 집 앞의 확장 월드로 이동합니다.
- 별빛 학교 노란 출입구에서 E → 로비의 '프롤로그/친구 찾기'에서 E → 기존 스토리를 이어갑니다.
- 로비의 '학교 사건 조사'는 메인퀘스트2로 연결됩니다. 기존 해금 조건은 유지됩니다.
- 우리 집 안에서도 현재 이야기를 이어갈 수 있습니다. F6으로 마을 탐험에 돌아옵니다.
- 건물 노란 출입구 E: 출입. 실내 출입구 E: 로비 또는 바깥 복귀.
- WASD 이동, Shift 달리기, Space 점프, Q 공격, Z 체력 물약, X 마나 물약.
- 퀘스트 장면은 기존 독립 공간을 유지하는 전환 방식입니다. 모든 스토리 맵을 하나로 합친 것은 아닙니다.

이동 시간
- 각 마을 중심 (31,26), (31,96), (31,166)의 간격은 70타일입니다.
- 기본 속도 3.5타일/초 → 인접 마을 중심 간 직선 보행 20초, Shift 5타일/초 → 14초.
- 미니맵 아래쪽으로 이어지는 중심 도로를 따라 이동합니다. 화면 기준으로 A+S를 누르면 월드 +y 방향입니다.
- 계산상 시간이며 실측값이 아닙니다. 마을 경계 간 시간과 길을 벗어나 걷는 시간은 다릅니다.

몬스터
- 스토리 탐험은 실제 메인퀘스트1 변신 단계가 끝난 뒤에만 야생 악몽을 생성합니다.
- 변신 전에는 공격할 수 없고 야생 몬스터는 0마리입니다.
- 변신 이후 숲/외곽에 총 50개의 몬스터 슬롯을 유지합니다. 마을 중심/실내는 안전합니다.
- 처치 시 약 3초 뒤 플레이어 및 처치 위치에서 최소 10타일 떨어진 후보지로 재생성합니다.
- 후보지가 모두 막혀 있으면 0.5초 후 재시도하므로 생존 수가 잠시 50보다 적을 수 있습니다.
- 실내 방문, 일시정지, 다른 장면 진행 중에는 야생 몬스터와 재생성 시간이 정지합니다.
- F1의 교사 대화 이후 변신은 독립 연습용이며 스토리 변신을 해금하지 않습니다.
- F2 사냥 연습의 기존 몬스터 규칙은 변경하지 않았습니다.
- F1/F6의 위치·체력·물약·야생 몬스터 상태는 모드 간 분리됩니다.
- 새 탐험 상태/지역 처치 수는 현재 실행 세션에만 유지됩니다. 기존 스토리 저장은 변경하지 않았습니다.

모니터링
- 기존 Start-Monitor.cmd로 열고 '활성 장면 따라가기'에서 F6 마을을 확인합니다.
- 각 마을 인구 10명, 지역별 생존 악몽 수, 이번 탐험 누적 처치 수, 안전도, 분위기를 표시합니다.
- 안전도 = max(0, 100 - 지역 생존 몬스터 수 * 4).
- 변신 전 평온, 변신 후 안전도 60 이상 경계, 미만 불안입니다.
- 지역은 마을 중심에 가장 가까운 y 구간으로 나눕니다. 바로 앞 시야 내 몬스터 수가 아닙니다.
- 분위기/안전도는 위 규칙으로 계산합니다. 소문과 성향은 설정값이며 사회 시뮬레이션이 아닙니다.
- JSON town 필드: population, nearby_monsters, defeated_monsters, safety_percent, source.
- 기존 스토리 장면처럼 수치를 측정하지 않는 장면은 추가 통계가 null입니다.

성능 및 수동 검증
- 32 x 32 지형 청크를 플레이어 주변에만 유지하고 기존 SceneGraph 가시성/깊이 정렬을 사용합니다.
- 고정 건물/장식은 유지형 Actor, 충돌은 4 x 4 타일 버킷의 주변 후보만 검사합니다.
- cpu.world.update_ms, cpu.world.outdoor_actor_sync_ms, cpu.world.interior_draw_ms,
  cpu.world.spawn_sites_build_ms, cpu.world.respawn_search_ms, cpu.world.spawn_gate_ms 기록.
- world.collision_tests_per_tick_count, world.wildlife_slots_count, world.spawn_sites_count,
  world.chunks_loaded/unloaded, world.monsters_spawned, world.spawn_retries 기록.
- CPU Scope 값은 중첩 구간을 포함합니다. 기존 GPU/프레임/프레젠테이션 로그와 구분해 비교합니다.
- 성능 향상 수치는 아직 측정하지 않았습니다.
- 사용자 합의에 따라 게임 빌드/실행은 수행하지 않았습니다.
- 정적 배치 검사: 21개 출입구/30명 위치 연결 및 중심 도로 무장애 확인.
- 프로젝트 XML 파싱, clang-format 검사, 모니터 JavaScript 문법 검사 확인.
- 모니터 가상 데이터 검사: 세 마을 카드/인구/안전도 표시와 기존 형식 호환 확인.
- 위 검사는 실제 OpenGL 화면/충돌 이동/전투 동작의 실행 검증을 대신하지 않습니다.

확인 순서
1. Visual Studio 빌드 후 프롤로그 집 출구 → 마을 → 학교 로비 → 스토리 이어가기 확인.
2. F6에서 21개 출입구 및 각 학교의 3개 실내 이동 확인. 편의점/보건소 상호작용 확인.
3. 마을 중심 간 기본 보행 시간을 측정하고 건물/나무에 길이 막히지 않는지 확인.
4. 변신 전 0마리, 변신 후 실외에서 50마리 생성, 처치 약 3초 후 다른 곳 재생성 확인.
5. F1/F2/F3/F4/F6 왕복 시 기존 퀘스트 단계와 체력/마나 HUD가 유지되는지 확인.
6. 브라우저에서 세 마을 각 10명, 처치 시 지역 통계 갱신, 비활성 장면 정지 표시 확인.
7. Release 실행 후 F5 성능 기록으로 청크 경계 이동/건물 출입/50마리 활성 상태를 비교.
8. tests/VillageWorldTests.cpp는 렌더러 없이 레이아웃/인구/기본 연결성을 검사하는 별도 테스트입니다.
