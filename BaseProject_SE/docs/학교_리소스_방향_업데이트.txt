학교 내부 확장 / resource 메시 교체 / 이동·공격 방향 수정

플레이 확인
- F6 마을 탐험 → 학교의 노란 출입 지점에서 E.
- 중앙 복도 36×14, 도서관 24×20, 체육관 32×26, 방송실 18×16.
- 1학년 1반/2반 각 24×20, 과학실/미술실 각 26×20.
- 복도의 이름표가 있는 문에서 E로 방에 들어갑니다.
- 방 아래쪽 출입구에서 E로 복도에 돌아옵니다. 복도 아래쪽 출입구는 학교 밖으로 연결됩니다.
- 학교 주변 부지를 넓게 확보했고 나무/야생 몬스터 생성에서 제외했습니다.
- 교실 책상·의자, 칠판, 도서관 책장, 방송실 장비, 체육관 벤치를 구분해서 배치했습니다.
- 오른쪽 실내 지도에서 내 위치와 출입구를 확인할 수 있습니다.
- F4 학교 퀘스트도 같은 복도/교실 자산을 사용합니다. 도서관/방송실은 실제 방 안에서 조사합니다.
- 퀘스트 체육관 전투는 기존 단계 해금에 따릅니다. 일반 방문은 F6 학교에서 가능합니다.

이동 / 공격 방향
- WASD는 화면 방향 기준입니다. 이동 입력은 월드 방향 벡터로 변환합니다.
- 마지막 이동 방향을 멈춘 뒤에도 유지합니다. 캐릭터는 그 방향의 8방향 메시를 표시합니다.
- Q 기본 공격은 공격을 시작한 순간 바라보는 방향으로 직진합니다.
- 가까운 적 때문에 반대편으로 자동 조준하던 처리를 제거했습니다.
- 튜토리얼/F6, 사냥터, 프롤로그/메인퀘스트1, 메인퀘스트2에 적용했습니다.
- 공격 자세와 투사체는 공격 순간의 방향을 공유하며 기존 투사체는 이후 방향을 바꾸지 않습니다.
- 지팡이 끝의 방향별 좌표를 모델과 함께 내보내므로 마법이 같은 지점에서 시작합니다.

resource 처리
- 입력: resource/magical_school_v02/MagicalSchool_Modular_Library_v02.blend.
- 원본 .blend는 수정하지 않았습니다. 원본을 수정한 뒤 변환 스크립트를 다시 실행할 수 있습니다.
- 변환: resource/export_runtime_models.py를 Blender의 --background --python 옵션으로 실행합니다.
- 출력: resource/runtime/school_models.bin 및 manifest.json.
- 기존 ModelId 45종을 포함한 기본 메시 67종과 플레이어 자세 11종×8방향=88개를 저장합니다.
- 캐릭터/몬스터/벚나무/바위/건물/지형/가구/아이템은 제공된 모델과 재질을 사용합니다.
- 모듈만 있는 건물/책장은 제공된 벽·지붕·창문·책·수납장으로 조립했습니다.
- 전용 원본이 없는 장치/퀘스트 소품은 제공된 소품을 조합했습니다.
- 그림자, 마법 이펙트, 공격 예고 범위, 체육관 라인 및 HUD는 렌더링 보조 도형을 유지합니다.
- 현재 렌더러에 맞춘 쿼터뷰 투영 메시와 샘플링한 걷기/공격 자세입니다. 런타임 스켈레톤 스키닝은 아닙니다.
- 구형 primitive_models_v8.bin보다 resource 팩을 우선 읽습니다. 팩 누락/손상은 콘솔 및 프로파일링에 기록합니다.
- Visual Studio 빌드 성공 시 실행 폴더의 resource/runtime에 메시 팩을 자동 복사합니다.
- 사용자 PC에 Blender를 설치하지 않아도 이미 변환된 메시로 게임을 실행할 수 있습니다.
- CharacterVisual.h가 방향별 지팡이 좌표와 발사점 변환을 담당합니다.
- 메시 정점은 불변 GPU 캐시를 사용하고, 학교 바닥/가구 Actor는 방 전환 전까지 유지됩니다.
- cpu.assets.resource_mesh_load_ms, assets.resource_mesh_count, assets.resource_pack_bytes,
  assets.resource_fallback_count, cpu.school.static_scene_build_ms, school.floor_tiles_count,
  school.fixtures_count, school.room_entries_count로 로딩/공간 구성을 확인할 수 있습니다.

검사 결과
- 변경 C++ 소스의 MSVC 문법 검사.
- CPU 검사: FacingAndSchoolTests, ResourceModelsTests, MainQuestTests, QuestTwoStoryTests.
- 8방향 발사, 뒤쪽 적 자동 조준 방지, 적 없는 상태 발사, 방향별 지팡이 소켓 일치 검사.
- 실제 가구 충돌 영역을 이용한 8개 실내의 입구/출구/중앙 조사 지점 연결 검사.
- 실제 C++ 로더를 이용한 67개 기본 메시/88개 방향 자세 읽기 검사.
- tools/validate_resource_models.py로 체크섬/정점 범위/방향별 메시 차이를 검사했습니다.
- 방향별 CPU 미리보기를 확인했습니다. 실제 게임 빌드/실행은 수행하지 않았습니다.

사용자 실행 확인 순서
1. Visual Studio에서 빌드 성공을 확인한 뒤 새 실행 파일로 시작합니다.
2. 이동 후 키를 놓고 Q를 눌러 상하좌우/대각선 8방향을 확인합니다.
3. 적을 등지고 Q를 눌러 뒤쪽 적으로 발사가 꺾이지 않는지 확인합니다.
4. 마법이 지팡이 끝에서 시작하며 걷는 몸 방향과 일치하는지 확인합니다.
5. F6 학교 복도/7개 방을 E로 왕복하고 책상 사이와 출입구 이동을 확인합니다.
6. F4 조사 3곳 → 복도 전투 → 체육관 전투의 기존 저장 진행이 유지되는지 확인합니다.
7. Release 성능 로그로 메시 교체 전후 프레임/CPU/GPU 시간을 비교합니다. 성능 개선 수치는 미측정입니다.
