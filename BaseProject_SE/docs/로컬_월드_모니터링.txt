로컬 브라우저 월드 모니터

1. 변경된 게임을 빌드하여 실행한다.
2. Python 3가 설치된 PC에서 tools/monitor/Start-Monitor.ps1을 PowerShell로 실행한다.
   또는: py -3 tools/monitor/server.py
3. http://127.0.0.1:8765 에 브라우저 창이 열린다. 종료는 서버 터미널에서 Ctrl+C.
   포트가 사용 중이면 server.py --port 8766 처럼 변경한다.
   HTML을 더블클릭해 file://로 여는 방식은 지원하지 않는다.

전송: 게임 → %LOCALAPPDATA%\Emberwick\world_monitor.json → 로컬 HTTP /api/state → 브라우저.
게임은 1초마다 JSON 파일을 임시 파일로 작성 후 교체한다. 브라우저도 약 1초마다 수신한다.
WebSocket/push가 아닌 HTTP JSON 폴링이며 게임에 외부 접속/명령을 허용하지 않는다.
서버는 127.0.0.1에만 바인딩하고 정해진 HTML/JSON만 제공한다. 외부 CDN/계정 불필요.
서버가 꺼져 있어도 게임은 동작한다. JSON 출력 실패도 게임을 중단하지 않는다.

NPC: 이름/ID/배치 여부/스크립트 상태/월드 좌표. NPC HP 시스템은 없어 null로 보낸다.
인구: 현재 장면에 배치된 NPC 수(플레이어 제외). 전체 세계 주민 수가 아니다.
몹: 살아 있는 적과 사망/리스폰 대기 적. 후속 단계에서 제거된 적은 누적하지 않는다.
분위기와 소문: 진행 단계/작성된 대사에서 온 설정값이다. 성향 시뮬레이션은 미구현 표시.
현재는 장면별 지역 묶음 하나를 제공한다. 독립 마을 시뮬레이션/평판/소문 전파는 추가하지 않았다.
비활성 장면은 정지 상태임을 표시하며 같은 학교의 여러 버전을 전역 합산하지 않는다.
5초 이상 새 스냅샷이 없으면 오래된 데이터 경고. 게임 창 최소화/정지 시에도 적용된다.
여러 게임 인스턴스 동시 실행은 지원하지 않는다(동일 스냅샷 파일 사용).

JSON: schema_version, session_id, sequence, timestamp_ms, active_scene, draw_calls_last_frame,
scenes[].{id,name,objective,active,paused,npc_count,mobs_alive,mobs_dead,towns,npcs}
브라우저 하단에서 전체 수신 JSON을 확인할 수 있다.

성능 로그: cpu.monitor.collect_ms / cpu.monitor.publish_ms / monitor.snapshots_written /
monitor.write_failures / monitor.snapshot_bytes. 게임 스레드에서 초당 한 번 파일 I/O하므로
느린 디스크에서 지연이 보이면 이 측정값으로 판단한 뒤 비동기 송신으로 분리한다.

수동 확인: NPC 대화/유나 귀가/적 처치/F1~F4 전환 시 값과 정지 표시가 맞는지,
게임 종료 후 오래된 데이터 경고, 서버 재시작 후 자동 복구, 저장 폴더 쓰기 실패 대응.
Python 실행 경로 문제
현재 PC에서는 기본 py 실행 별칭이 동작하지 않는 것을 확인했다.
Python 3를 설치하거나 Start-Monitor.ps1 -PythonPath "Python 실행 파일의 전체 경로"로 실행한다.
Codex 내장 Python으로 서버 문법 및 응답 처리 5개 항목을 별도 검증했다.
실제 게임 연동, 브라우저 화면 및 게임 HUD 화면은 사용자 실행 확인이 필요하다.
