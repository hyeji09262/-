게임소프트웨어공학 프로젝트 초기 게임 기획서
버전: 0.1 / 작성일: 2026-09-09
게임명: 미정

1. 기획 개요

실시간 렌더링을 기반으로 한 싱글플레이 2.5D 쿼터뷰 오픈월드 RPG를 제작한다.
플레이어는 마법사가 되어 지역을 탐험하고 보스를 물리치며 성장한다.
보스 처치로 얻은 스킬은 전투 능력뿐 아니라 탐험 가능 범위를 넓힌다.
새롭게 접근한 장소에서 보상을 획득하고 다음 보스에 도전하는 순환이 핵심이다.
게임소프트웨어공학 과목 프로젝트로서, 작은 플레이 구간에서 이 순환을 먼저 완성하고 확장한다.

2. 확정된 기본 방향

- 플레이 방식: 싱글플레이. 멀티플레이와 온라인 서비스는 기본 범위에 포함하지 않는다.
- 장르: 오픈월드 RPG.
- 화면 표현: 쿼터뷰 시점의 2.5D 표현과 실시간 렌더링.
- 세계관: 판타지. 현재 개발 지침의 긴 황혼 세계를 기본 배경으로 삼는다.
- 분위기: 다크한 세계에 유머와 개성 있는 인물을 결합한다.
- 주인공: 보스를 물리치며 성장하는 마법사.
- 핵심 성장: 보스 처치 후 스킬을 선택·강화하고, 그 스킬로 탐험하여 추가 보상을 얻는다.
- 기술 기반: 기존 C++ / OpenGL / FreeGLUT / GLEW / Visual Studio 프로젝트를 점진적으로 확장한다.

이 기본 틀을 유지한다. 지역명, 인물명, 세부 사건, 스킬 수치 및 아래 예시 콘텐츠는 초기 제안이며 확정 설정으로 간주하지 않는다.

3. 기획 의도와 핵심 재미

가. 성장의 체감
새로운 마법을 얻었을 때 공격력뿐 아니라 할 수 있는 행동이 달라지게 한다.

나. 발견과 재방문
처음에는 지나쳤던 틈, 봉인, 장치 등을 기억하게 하고, 새로운 스킬을 얻은 후 돌아갈 이유를 제공한다.

다. 전투와 탐험의 연결
보스가 탐험 능력을 제공하고 탐험 보상이 다음 전투의 준비가 되게 한다.

라. 분위기의 대비
위험하고 쇠락한 세계의 긴장감을 유지하면서 마법사의 실수와 기묘한 주민을 통해 웃음을 준다.
중요한 희생이나 보스의 위협을 매번 농담으로 무효화하지 않는다.

4. 시간적 배경과 세계관

기본 배경은 긴 황혼이 이어지는 판타지 세계다.
구체적 연도, 기술 수준과 황혼의 원인은 추후 확정한다.

세계관 초안:
태양의 빛이 약해진 사건 이후 수십 년이 지나, 마을과 왕국은 쇠퇴하고 폐허에는 마물과 저주가 퍼졌다.
지역마다 다른 마법적 이상 현상이 발생하며, 이를 지배하는 보스가 존재한다.
생존자들은 작은 거점에서 살아가고, 플레이어는 거점과 위험 지역을 오가며 세계의 비밀을 알아간다.

유머 예시:
- 비밀을 큰 소리로 떠드는 저주받은 장비.
- 무서운 외형과 달리 사소한 고민으로 의뢰하는 언데드 주민.
- 마법 실험에 실패하고도 당당하게 변명하는 마법사.

5. 스토리 구성

확정된 중심 서사:
미숙한 마법사가 여러 보스와 맞서고 마법을 익히며 성장하여 최종 보스에 도전한다.

세부 줄거리 초안:
도입: 작은 거점에서 생활하던 주인공이 사건을 겪고 바깥 세계로 나선다.
전개: 지역 문제를 해결하고 보스를 처치하며 마법 핵심과 세계의 단서를 얻는다.
심화: 새로운 능력으로 접근한 유적에서 황혼의 원인과 보스들의 관계를 발견한다.
절정: 성장한 마법사가 최종 보스와 대결한다.
결말: 주인공의 행동이 세계와 주민들에게 남긴 변화를 보여준다.

사라진 스승, 태양을 감춘 마왕, 더 큰 재앙을 막기 위한 황혼, 분기 엔딩은 이전 대화의 후보 설정이다.
모두 필수 구현 사항은 아니며 상세 시나리오를 정할 때 채택 여부를 결정한다.

6. 핵심 플레이 순환

지역 탐험 → 막힌 경로와 보스 발견 → 보스 처치 → 마법 핵심·스킬 포인트 획득
→ 스킬 선택·강화 → 새 능력으로 탐험 또는 재방문 → 보상 획득 → 다음 보스 도전

플레이 예시:
1) 플레이어가 시작 지역에서 통과할 수 없는 그림자 장벽과 그 너머의 유적을 발견한다.
2) 지역 보스를 처치하여 그림자 계열을 열고 스킬 포인트를 얻는다.
3) 기본 통과 능력을 얻으며, 포인트로 돌진 거리나 전투 효과 등을 선택해 강화한다.
4) 장벽으로 돌아가 유적에 진입한다.
5) 유적에서 장비 또는 주문 강화와 다음 지역에 관한 단서를 얻는다.

7. 성장과 스킬 시스템

- 보스 처치는 마법 핵심과 스킬 포인트를 제공하는 주요 성장 계기다.
- 핵심은 해당 마법 계열과 기본 탐험 기능을 연다.
- 플레이어는 스킬 포인트로 전투·이동·탐색 능력을 선택하거나 강화한다.
- 메인 진행에 필수인 탐험 기능은 기본으로 보장하여 스킬 선택 때문에 진행이 막히지 않게 한다.
- 선택 스킬은 플레이 스타일과 선택 지역의 접근 방식에 차이를 만든다.
- 필수 스킬을 얻으려면 그 스킬 자체가 필요한 순환 잠금을 만들지 않는다.
- 포인트 지급량, 트리 규모, 재분배 가능 여부와 비용은 미정이다.

마법 계열 후보:
그림자: 돌진과 숨겨진 통로 진입. 보상 후보는 비밀 유적과 희귀 장비.
번개: 장치 작동과 연쇄 공격. 보상 후보는 연구소와 상위 주문.
중력: 지정 장애물 이동과 낙하 제어. 보상 후보는 지하 공간과 강화 재료.
시간: 지정된 파손 구조물 복원과 일시 정지. 보상 후보는 과거의 기록과 스토리 단서.

시간 마법은 전체 게임 상태 되감기보다 정해진 대상에 한정한 상호작용부터 검토한다.
초기 구현에서는 한 계열만 사용하여 성장과 탐험의 연결을 확인한다.

8. 월드와 탐험

- 거점, 일반 탐험 구역, 선택 유적, 보스 구역으로 지역을 구성한다.
- 자유롭게 탐험할 수 있는 경로와 능력 획득 후 열리는 경로를 함께 배치한다.
- 오픈월드는 최종 지향점이며, 초기에는 작은 연결 지역으로 재미와 구조를 검증한다.
- 새로운 능력으로 기존 지역에서 얻을 수 있는 보상을 최소 하나 이상 제공한다.
- 선택 보상은 장비, 주문, 강화 재료, NPC 진행, 세계관 단서 중 목적이 명확한 것으로 설계한다.
- 지역 수, 전체 맵 크기, 보스 순서의 자유도, 절차적 생성 여부는 미정이다.

9. 전투·상호작용·보스

전투는 실시간 조작을 기본 설계 방향으로 두되, 구체적 입력 방식은 추후 확정한다.
초기 전투 범위는 이동, 기본 마법 공격, 피격·체력, 적 사망, 보스 패턴으로 제한한다.
보스는 공격 전조와 대응 기회를 제공하며, 처치 후 얻는 마법과 지역 특성이 연결되게 한다.
보스 처치 보상의 중복 지급을 방지하고 처치·획득 상태를 기록한다.
NPC 상호작용은 짧은 대화와 목표 안내부터 시작한다.

10. 화면과 사용자 인터페이스

- 쿼터뷰에서 캐릭터, 지형, 마법 효과와 보스 공격 전조를 구분하기 쉽게 표현한다.
- 지면 기준 위치에 따른 앞뒤 가림과 높이 표현을 일관되게 처리한다.
- 기본 UI 후보: 체력, 현재 사용 스킬, 상호작용 안내, 보스 체력, 스킬 선택 화면, 보상 안내.
- 잠긴 경로에는 필요한 능력을 추측할 수 있는 시각적 단서를 둔다.
- 픽셀 아트 여부, 타일 비율, 카메라 각도, 해상도와 입력키는 미정이다.

11. 기술 설계 방향

- 월드 좌표 (x, y, z)와 화면 좌표를 분리하고 z는 높이로 사용한다.
- 충돌·이동은 월드 좌표에서 처리하고 렌더러가 쿼터뷰 화면 좌표로 변환한다.
- 투영식의 Y축 방향은 렌더러 좌표 관례와 일치시키고 입력 변환에도 같은 기준을 사용한다.
- 월드는 청크로 나누며 현재 지침의 초기 기준은 32×32 타일이다. 필요시 근거를 갖고 조정한다.
- 카메라에 보이는 범위를 중심으로 렌더링한다.
- 스프라이트 지면 기준점으로 깊이를 정렬하고 큰 건물·높이 차이의 가림은 별도로 검토한다.
- 입력, 업데이트, 렌더링, 월드 데이터, 엔티티 행동을 분리한다.
- 이동 등 실시간 업데이트에는 델타 타임을 사용한다.
- 저장 대상 후보는 위치, 스킬, 보스 처치, 획득 보상, 열린 경로와 퀘스트 상태다.
- 기존 기술 스택과 프로젝트 구조는 점진적으로 확장한다.

12. 현재 상태와 초기 구현 범위

현재 소스 분석 기준으로 창 생성, 입력 콜백, 단색 사각형 렌더링이 존재한다.
쿼터뷰 월드, 이동·충돌, RPG 전투, 보스, 스킬 트리와 저장 기능은 향후 구현 대상이다.
실제 빌드 및 실행 성공 여부는 이 기획서 작성 중 검증하지 않았다.

첫 플레이 가능한 구간의 목표:
- 작은 탐험 지역 하나와 플레이어 이동·카메라·충돌.
- NPC 하나, 일반 적 한 종류, 보스 하나.
- 기본 마법 공격과 보스 처치 판정.
- 보스 보상, 기본 탐험 능력과 선택 강화.
- 새 능력으로 접근할 수 있는 장소 하나와 의미 있는 보상 하나.

완료 판단 기준:
플레이어가 막힌 장소를 발견하고 보스를 처치한 뒤, 스킬을 선택하고 돌아와 보상을 얻는 과정을 끝까지 수행할 수 있다.
포인트 선택 때문에 필수 진행이 막히지 않고 보상도 중복 지급되지 않는다.

13. 단계별 개발 순서

1단계: 게임 루프, 입력 상태, 쿼터뷰 좌표계, 카메라와 기본 렌더링.
2단계: 작은 맵, 플레이어 이동, 충돌과 상호작용.
3단계: 기본 전투, 일반 적과 보스 한 종류.
4단계: 보스 보상, 스킬 선택과 탐험 경로 해금.
5단계: 탐험 보상, 진행 상태 저장·불러오기와 사용자 검증.
6단계: 완성된 순환을 바탕으로 청크·지역·콘텐츠 확장.

일정과 각 단계의 분량은 수업 제출 기한 및 작업 인원 확인 후 정한다.

14. 범위 관리와 위험 요소

오픈월드 콘텐츠 과다: 지역 수를 늘리기 전에 첫 플레이 구간을 완성한다.
쿼터뷰 가림 문제: 캐릭터 기준점, 장애물과 높이의 기준을 먼저 정한다.
스킬 진행 막힘: 필수 능력 보장과 경로 의존성 검토로 예방한다.
복잡한 마법 구현: 정해진 대상에 적용되는 작은 기능부터 구현한다.
미확정 설정 확대: 새로운 세계관과 시스템은 제안으로 표시하고 기본 요구와 구분한다.

15. 개발 협업 원칙

- 프로젝트의 지속적인 작업 기준은 AGENTS.md를 따른다.
- 이 문서는 사용자 열람용 초기 기획서이며 기본 방향 변경 시 관련 지침도 함께 검토한다.
- 특별한 상황이 아니면 빌드와 실행 결과 확인은 사용자가 직접 한다.
- Codex는 코드 분석·설계·수정 및 필요한 수동 확인 항목을 제공한다.
- 기존 변경 사항을 보존하고, 작은 단위로 구현한다.
- IDE 개인 설정과 빌드 산출물은 Git 추적에서 제외한다.
