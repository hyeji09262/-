렌더링 최적화 및 성능 로그 — 2026-09-23

1. 이번 변경과 게임 시스템 관계
전투·경험치·충돌·조작키·마법봉 소켓은 유지한다. 변경 대상은 렌더링 제출과 장면 준비 비용이다.
SceneGraph가 투명 오브젝트의 바닥 깊이 순서를 결정하고 Renderer가 그 순서를 유지하여 제출한다.
물/마법/도형/문자는 공통 스트림 셰이더를 사용한다. 문자열이나 물 타일 하나마다 Flush하지 않는다.
연속 모델은 하나의 순서 보존 인스턴스 배치로 묶는다. 모델 사이에 효과/문자가 끼면 순서를
보존하기 위해 배치를 나눈다. 전역 셰이더별 정렬로 투명 가림 순서를 훼손하지 않는다.

2. 정적 Actor와 GPU 모델 캐시
첫 레벨 지형·소품, 튜토리얼 지형·소품은 처음 등록한 Actor와 콜백을 재사용한다.
맵 변경 시 Clear한다. 동적 캐릭터·투사체·드롭 등은 기존 동기화와 수명 관리를 유지한다.
SceneGraph에서 화면 밖 Actor를 정렬 전에 제외한다. 컬링 마진은 큰 소품을 고려한 보수적 값이다.
전체 노드 순회는 아직 존재한다. 더 큰 월드에서는 청크별 후보 조회가 후속 최적화 대상이다.
모델 정점은 GPU texture buffer에 최초 등록하며 이후 위치·크기·모델 범위만 업로드한다.
새 애니메이션 모델이 처음 등장하면 캐시가 확장되어 한 번 재업로드될 수 있다.
현재 모델 데이터는 렌더러 수명 동안 주소와 내용이 불변이라는 계약이다. 실시간 모델 편집이나
언로드를 추가한다면 캐시 무효화/세대 ID를 먼저 구현해야 한다.
다른 정점 수의 모델을 한 인스턴스 배치에서 그리므로 남는 정점은 클리핑된다.
render.model_submitted_vertices / render.model_useful_vertices 비율이 지나치게 높으면
순서를 유지하는 모델 크기 구간별 배치를 검토한다.
GPU texture buffer 용량 제한에 닿으면 도형 스트림 경로로 폴백하며 횟수를 기록한다.

3. 블룸
가로·세로 1/4 크기(면적 1/16)에서 밝기 추출, 가로 블러, 세로 블러를 수행한다.
마지막 전체 화면 합성은 원본과 블룸 두 텍스처를 읽는다.
후처리 draw call은 1→4로 늘지만 기존 전체 화면 25탭 블러를 제거한다.
효과의 모양과 밝기가 약간 달라질 수 있으므로 사용자가 화면을 비교해야 한다.

4. 로그 위치와 제어
기본 활성화. %LOCALAPPDATA%\Emberwick\profile_<프로세스ID>_<실행식별자>.jsonl
F3으로 프로파일링/로그를 끄거나 다시 켠다. 기존 F1/F2와 전투 키는 유지한다.
실행 전 EMBERWICK_PROFILE=0 환경 변수를 설정하면 로거 초기화를 생략한다.
이 경우 실행 중 F3으로 켤 파일이 없으므로 다시 시작해야 한다.
1초 단위 JSON Lines 집계. 종료 시 남은 집계를 기록한다.
동일 실행에서 파일당 16 MiB, 기본 파일과 _part1/_part2 세 파일을 순환한다.
약 48 MiB를 넘으면 해당 실행의 가장 오래된 로그부터 덮어쓴다. 다른 실행 로그는 건드리지 않는다.
로그 폴더는 저장소 밖이며 자동 업로드하지 않는다. 프레임 버퍼/게임 화면/사용자 입력은 기록하지 않는다.
로깅 실패 또는 권한 문제 시 HUD에 로그 OFF가 표시되며 게임은 계속 실행한다.

5. AI가 해석할 스키마
schema_version: 1. event: session_start, performance_window, log_rotated.
session_start: Debug/Release, GPU 렌더러 문자열, OpenGL 버전.
performance_window: unix_ms, frame_end, scene(창의 마지막 장면), window_ms,
frame_interval_p95_ms, timings_ms, counters_sum, gauges_last.
장면 전환이 포함된 집계는 frame.scene.tutorial/level_one의 값으로 구분한다.
timings_ms 각 항목: samples, sum, mean, max. 단위는 밀리초.
counters_sum: 집계 구간 내 누적 횟수/바이트. 프레임당 값은 render.frames로 나눈다.
gauges_last: 마지막 관측 상태. 단위는 키의 _bytes, _pixels 등으로 표시한다.
GPU 결과가 아직 준비되지 않으면 해당 측정값을 생략한다. 누락은 0 ms가 아니다.
CPU Scope는 inclusive이므로 부모·자식 시간을 합산하면 중복 계산된다.
GPU timestamp는 해당 제출 구간의 타임라인 경과시간으로 CPU 공급 지연도 포함할 수 있다.
GPU 순수 연산 점유율이나 CPU와 GPU 시간의 단순 합이 프레임 시간이라고 해석하지 않는다.

6. 주요 관측 지점
frame.interval_ms: 실제 렌더 콜백 간격. FPS = 1000 / mean.
cpu.frame_callback_ms: 프레임 콜백, swap 대기 포함.
cpu.present.swap_wait_ms: 버퍼 교환 호출 시간(VSync/드라이버 대기 포함 가능).
simulation.tick_interval_ms / delta_time_clamped: 업데이트 간격과 dt 제한 횟수.
cpu.gameplay.*: 업데이트, 적 AI, 투사체, 아이템 처리.
cpu.navigation.bfs_ms / navigation.bfs_requests: 경로 탐색 비용.
cpu.collision.move_ms / collision.walkable_checks: 이동·충돌 비용.
cpu.map.* / cpu.scene.static_build_ms: 맵 생성/정적 장면 최초 생성 비용.
cpu.scene.sync_ms / collect_cull_ms / sort_ms / dispatch_ms: 장면 준비 단계.
scene.*: 생성·제거·동기화·스캔·정렬 전 제외·큐 진입·현재 Actor 수.
cpu.render.*: 텍스트 레이아웃, 모델 요청, GPU 업로드/제출, 후처리 제출.
render.draw_calls.*: 실제 OpenGL 제출. 혼합 배치는 mixed에 한 번만 센다.
render.effect_requests / text_requests: 요청 수. 실제 draw call 수와 다르다.
render.batch_break.*: 파이프라인 전환 또는 정점 한도로 인한 배치 분리.
upload.*_bytes: 스트림/모델 캐시/인스턴스/글꼴 GPU 업로드량.
render.model_cache_*: 캐시 재사용·최초 등록·용량 제한 폴백.
cpu.font.rasterize_ms / font.glyph_cache_misses: 첫 한글 글리프 생성 비용.
cpu.assets.* / cpu.storage.*: 셰이더·모델 캐시·성장 저장/불러오기 비용.
gpu.timeline.world_ms / post_ms / ui_ms / frame_ms: 비동기 GPU timestamp 결과.
gpu.query_ring_full_frames / completed_samples / sample_age_frames: 측정 지연/누락.
memory.*: 앱이 관리하는 버퍼·텍스처·큐의 크기 추정(드라이버 실제 VRAM/RSS가 아님).
opengl.errors / last_error_code: 120프레임마다 제한적으로 수집하는 GL 오류.
cpu.profiler.write_ms / gpu_poll_ms: 로깅 자체의 비용.

7. 지속적인 확장
새 시스템에는 Performance::Scope scope("cpu.system.operation_ms"); 를 배치한다.
반복 횟수는 Count("system.requests"), 현재 상태는 Gauge("system.live_objects", value).
키는 고정된 영어 dotted name과 명시적 단위를 사용한다. 오브젝트 ID를 키에 붙여
항목 수를 무한정 늘리지 않는다. 정점마다 타이머를 넣지 말고 작업 묶음을 측정한다.
GL 타이머는 8개 슬롯의 지연 조회이며 결과를 기다리거나 glFinish를 호출하지 않는다.
대규모 미래 시스템의 모든 비용을 자동 검출하는 도구는 아니다. 새 시스템에 계측 지점을 추가한다.
스레드를 추가할 경우 현재 단일 스레드 로거를 직접 공유하지 말고 스레드별 수집을 구현한다.

8. 검증 절차(빌드/실행은 사용자 담당)
Release x64에서 학교 정지, 바다가 넓게 보이는 위치, 전투/드롭, F1 튜토리얼을 각 30초 기록한다.
초기 모델/글리프 생성 구간과 안정 상태를 분리한다. 해상도·위치·적 수를 맞춰 비교한다.
F3 ON/OFF로 계측 오버헤드도 비교한다. Debug와 Release를 섞어 성능 개선률을 계산하지 않는다.
한글, 물결, 반투명 그림자, 왼쪽/오른쪽 마법, 나무 뒤 가림, 창 크기 변경,
맵 재생성과 F1/F2 반복 전환을 확인한다.
tests/SceneGraphTests.cpp에 정렬 전 컬링과 정적 Actor 유지 테스트를 추가했으나 실행하지 않았다.
tools/Analyze-Performance.ps1 -Path <로그경로> 는 읽기 전용 JSON 요약을 표준 출력으로 반환한다.
여러 파일을 전달할 때 같은 파일을 중복 전달하지 않는다. 마지막 미완성 줄은 집계에서 제외한다.
평균 FPS/draw call, 단계별 시간, p95, 업로드량을 근거로 후속 개선을 결정한다.
현재 실제 게임 실행 결과나 FPS 개선 수치는 검증하지 않았다.
